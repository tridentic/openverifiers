1. A robust DSL language
   1. Domain-specific packages, authorable like code: `import physics`
   2. Define a scenario. Supports domain-specific types of Facts, Transformation and Controller. Native equation/inequality support (basically fundamental math is native; topology etc. a separate `math` package). Core types are Fact, Transformation, Controller/Generator etc. Powerful, robust syntax. It can be generated by an Agent, or auto-derived using algorithmic solvers (later planned).
   3. Basically syntactic-sugar-driven logic needs to be broken down into fundamental Facts and relations between them.
2. `ov` CLI/Runtime
   1. Accept `ov program.ov --verbose` etc. commands, or be exposed as a library instead.
   2. OV (high-level) → RawOV (with fundamental facts, transformations) → OVTrace (entire program graph walked through) —(success)→ OVState. The OVState becomes a trusted program state which can later be imported and used again.
3. OKQL: Knowledge Query Language
   1. We can either check whether a certain fact or a near match was derived.
   2. Basically this has a lot of potential.
4. OVProver (our most ambitious one)
   1. Based on a certain target definition, the prover generates a program which satisfies the target, or tries to satisfy the maximum.
