## 5. Deviations

1. **What counts as a "package file" for the meaning gate (D-025).** The
   gate excepts two kinds of package file:
   - `benchmarks/**/case.ov`: problem statements, which the faithfulness lint
     (F2 bars any `law`, `axiom` or `definition` in a case) and the gold-blind
     reviewer check;
   - test fixtures (`tests/**`): MP-DOL leaves tests free.

   Everything else that declares `package` is gated. If you want case files
   gated too, every new formalization needs a founder approval. I recommend
   against that.
2. **Earlier reports keep the founder's name as written.** Rewriting the four
   reports from before today was blocked as an edit to existing records, so
   they stay as written; every new file uses "the founder". `pyproject.toml`'s
   `authors` field also still names a person. That is package metadata and
   public naming, which is the founder's call, so it goes into the approval
   packet, Part D.
3. **The APPROVERS file needed no approval to create.** Writing down the
   default (`founder`) leaves the set of roles unchanged, and the gate checks
   only changes to that set. The alternative would have needed a founder
   trailer on my own commit.

## 6. Shortcuts found

1. **A commit could have added itself as an approver.** The first gate draft
   treated a new `APPROVERS` file as "new gold" (free), so a commit could
   create it with a new role. I caught this with a test before the commit; the
   gate now compares the role sets.
2. **The gold trailer used to accept any human name.** With `APPROVERS`, only
   the listed role approves. A test that accepted `A. Reviewer` now expects
   rejection; it is listed as a test change.
