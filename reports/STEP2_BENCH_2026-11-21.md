## 5. Benchmark scaffold and `ov bench` (`1e34e64`, `0bf5eb1`, `ac2086a`)

**Usage:** `ov bench [DIR] [--suite S] [--case C] [--seeds N] [--out DIR]
[--strict] [--no-reductions]`

**Layout:** `benchmarks/<suite>/<case>/{case.ov, expected.json}`

**Gold format.** Per query, in file order:
- `verdict`, plus optional `values`, `assumptions`, `reason`, `missing`
  (predicate names) and `names`;
- each query entry also carries the query's text, which the harness checks,
  so gold never attaches to a different query;
- class checks by title;
- an `error` code list for files that must be rejected;
- every entry has a `why`.

Values compare as quantities (500 g = 0.5 kg). A kernel rejection is
recorded as `not_stratifiable`; any other exception is `crash:<Type>` and
never matches gold.

**Seeds.** `--seeds N` reruns each case with z3 seed base `100 * seed`
(`objects.solve.seed_base`; the default 0 is unchanged).

**Outputs:**
- `results.jsonl`: one row per case and seed;
- `summary.csv` and `summary.md`, with per suite:
  - false PROVEN and false REFUTED;
  - UNKNOWN precision and recall;
  - p50 and p95 over all runs;
  - cases whose outcome varies across seeds.

All three changes to the harness's comparison rules were committed before
any gold existed: values as quantities, recording rejections, and the
`not_stratifiable` code.

**In the suite:** `test_benchmark_suites_against_gold` runs the bench and
asserts no crash, no false PROVEN or REFUTED, and that the failing set is a
subset of the three known mismatches. A new failure turns CI red. A fix
means removing the case from that list, never editing gold.

**Side fix:** `import openverifiers.objects` was circular on its own, and
worked only when `lang` happened to load first. `lang/__init__` now loads
its names lazily.
